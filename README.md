# School WiFi Connect

[下载最新版](https://github.com/li-zane/school-wifi-connect/releases/latest)

解压 Windows-x64.zip 后运行 `NJUSTWiFi.exe`，无需安装 Python；使用系统的 Edge WebView2 Runtime。请把整个目录放在自己可写的位置。

右上角“检查更新”支持检查正式发布、下载校验、安装并重启。新版本启动失败会自动恢复旧版。旧于 3.7.0 的版本需先手动下载一次。

账号、密码、备用网络与日志仅保存在 `%LOCALAPPDATA%/NJUSTWiFi`，不上传 GitHub；分享时只分享发布 ZIP。

## 使用

Windows 10/11 x64 发布包完整解压后双击 `NJUSTWiFi.exe`，打开独立桌面窗口。需要系统已有 Microsoft Edge WebView2 Runtime 与 .NET Framework 4.6.2 或更新版（当前 Windows 通常已包含）。后端固定监听 `http://127.0.0.1:18089`，也可从浏览器访问。

最小化仅收起窗口，任务栏图标保留。关闭窗口时可选择“退出程序”或“关闭到托盘”，并可记住选择；高级设置可改为每次询问、托盘或退出。关闭到托盘会释放网页窗口进程，保留轻量托盘与后台；双击托盘或再次打开 EXE 可重开窗口。托盘“退出界面”退出托盘和窗口，保留网络监控；“退出程序”同时停止后台。后端通过当前用户的 Windows 任务计划程序独立运行，不依赖桌面窗口。“开机启动”控制登录前联网任务及登录后的用户后台（首次设置需管理员确认），“启动后自动监控”控制是否自动检测。关闭开机启动会移除登录前任务及登录触发，不中断当前用户后台。

监控开启并已配置网络时，检测到 WiFi 软件开关关闭会自动尝试开启，再按校园网、备用列表的原顺序恢复连接。WiFi 已开启时只读取状态，不重复设置；正常状态不新增开关日志。开启失败后按 30 秒、1 分钟、2 分钟、4 分钟、5 分钟退避重试，此后最长每 5 分钟重试；也可点“立即检测”。需要保持 WiFi 关闭时，先暂停监控。硬件开关关闭、无线网卡被禁用或系统拒绝设置时显示简短提示，保留原状态并稍后重试；程序不修改飞行模式总开关、不启用被禁用的网卡。开关恢复调用 Windows WLAN API，不新增依赖或常驻轮询线程。

设置中的 `NJUST WIFI` 是校园网 SSID，默认仍为 `NJUST`。它留空或未配置校园账号时，只使用备用 WiFi。备用列表最多 8 项，可添加、删除和上下调整顺序；检测恢复时先尝试校园网，再按列表顺序尝试备用网络，每项失败继续下一项。备用网络运行正常时，后续周期仍会尝试恢复更高优先级的网络。

备用密码填写后通过 Windows WLAN API 在内存中创建当前用户的 WPA2-Personal/AES 网络配置，不生成含密码的临时 XML 文件。密码应为 8–63 位 ASCII 字符或 64 位十六进制密钥；密码留空复用 Windows 已有网络配置，其他认证类型请先在 Windows 中连接并保留密码为空。NJUST WIFI 账号与各备用密码会在设置页回填，备用密码默认可见，可点眼睛按钮隐藏；校园密码可点眼睛按钮显示。应用中未填写备用密码时，设置页仅按已配置的 SSID 读取 Windows 保存的密码显示，不导出 XML，也不因显示而把密码写入应用配置；Windows 未保存或未授予读取权限时保持空白。

高级设置中的“认证域”是学校认证接口用于区分账号所属域的字段，通常保留 `default`；NJUST WIFI 账号和密码是学校门户登录信息，与备用无线网络密码不同。认证服务器固定为 `m.njust.edu.cn`。

代理兼容按请求自动处理，无需手动开启。普通连接仍绕过系统 HTTP 代理；识别到常见 TUN 网卡、Fake-IP（`198.18.0.0/15`）或直连探测失败时，改用绑定物理 WiFi 网卡与源地址的连接，并向该网卡的 DNS 查询真实 IPv4。联网检测、程序内校园认证和余额查询共用这套分支，不需要打开网页，也不修改系统代理、路由、DNS 或其他应用的流量。HTTPS 保留原始域名和证书校验，认证超时不会在另一路径重复提交同一请求。

代理兼容通路不确定时会保留当前 WiFi，显示短提示并按现有失败退避稍后重试；学校只读接口确认已认证而外网探测失败时，也不会因此反复认证或切换备用网络。明确未认证后仍执行原认证流程，其他明确失败仍按备用列表顺序处理。该通路依赖 Windows 提供的物理 WiFi IPv4 与可用 DNS；TUN 的防火墙或阻断规则仍可能阻止网卡绑定连接，程序不会自动关闭代理。高级设置额外打开的系统浏览器页面仍遵循浏览器自己的代理设置，兼容分支只作用于本程序请求。

桌面界面参考 GPT Image API 的 `gpt-image-2.6` 设计图，由 Antigravity 的 Gemini 4 Hydrogen（XHigh）直接编写 HTML/CSS/JS 并完成美化；Codex 负责审查、交互回归、Bug 修复与打包。浅红侧栏、浅蓝工作区，状态页集中显示连接、余额与后台概览；设置、守护、日志各用独立内容空间。四页视口保持一致，长内容内部滚动；侧栏支持上下方向键，帮助按钮可重放新手引导，反馈为顶部居中 Toast。日志支持关键词与日期联合筛选，备用列表提供顺序图标按钮和数量提示。默认窗口为 1120×780，最小为 860×620，针对桌面缩放布局，不提供移动端界面。Logo 放在粉色侧栏内，窗口控制按钮融入内容页右上角；支持拖动、缩放与最大化，最小化保留任务栏，关闭行为可配置。面板不使用磨砂模糊，不引入字体下载、前端框架、大图背景或持续动画。品牌 WiFi 图形由可编辑 SVG 导出，侧栏、网页图标、标题栏、托盘和 EXE 统一使用淡红淡蓝标识；运行时只加载 96px WebP 和多尺寸 ICO，设计参考大图不加入运行包。

四页下方内容框随窗口高度统一布局，长设置、程序和日志在框内滚动。高级设置“认证时打开学校登录页”会在尝试校园网认证时额外打开系统浏览器，关闭后仍会自动认证。

首次使用且尚未配置网络时，界面会显示五步短引导：校园账号、备用 WiFi、自动保存、开始监控、程序守护。右上角问号可随时重新查看，支持跳过、上一步和 Esc 退出。引导只切换页面和定位控件，不自动保存设置、联网或启动程序；已有配置的用户不会自动弹出。

## 隐私

- 账号直接发送到学校门户，不经过作者服务器；无遥测、广告、在线字体、云端账号或远程前端资源。
- 默认校园凭据只保留在内存。“记住账号”将校园账号密码保存为本机 JSON；备用网络及其密码随设置保存为本机 JSON，不加密。配置和日志存放在 `%LOCALAPPDATA%\NJUSTWiFi`，发布包不包含这些个人数据。
- 设置页通过本地会话保护的 `/api/credentials` 读取真实校园账号密码，配置接口读取备用密码；状态和诊断接口不返回凭据。空校园账号和空校园密码保持原值。输入框离开时自动保存，开关和排序立即保存；保存响应不覆盖正在编辑的内容，校验失败保留输入并提示。浏览器存储只保存主题和新手引导完成/跳过标记，不保存凭据；桌面 WebView2 关闭密码自动保存与自动填充。
- 页面关闭或浏览器隐藏后停止前端轮询；后端按设定间隔休眠，失败时 30 秒起指数退避，最长 5 分钟。
- 日志仅保留固定状态消息，不记录门户响应正文、账号、密码、SSID、IP、MAC 或个人路径。磁盘日志最多约 768 KiB；界面只保留最近 100 条事件。
- 导出的诊断报告采用字段白名单，不包含配置、凭据或设备标识。
- 余额只向学校查询，先后核对在线账号与配置账号；只在内存缓存，不写入日志、诊断或分享包。联网检测成功后最多每 5 分钟自动刷新，也可手动刷新。离开校园网或账号不一致时显示查询状态；从未获取成功时显示“—”，零余额显示 0.00。
- 连通性探测默认访问微软/小米的公开检测端点，可在高级设置中修改。校园认证遵循现有门户 HTTP 协议；认证请求不跟随重定向。代理兼容分支在本机内存中使用网卡地址和 DNS，不将这些信息写入日志或诊断；诊断仅增加 `connection_path` 状态（`normal`、`wifi-direct` 或 `unavailable`）。

本地接口仅监听 `127.0.0.1`，通过主机、来源和会话令牌校验保护写操作；静态资源只允许固定路径。端口冲突直接报错，不自动换端口。

## 从源码运行

安装 Python 3.11 或更新版本。运行时没有第三方依赖。

```powershell
python -B app.py
```

本机日常使用双击 `Start-NjustWifi.pyw`，存在当前版本的桌面构建时打开桌面端；未构建时使用源码后端与浏览器。或用系统 Python 注册后启动：

```powershell
.\scripts\startup.ps1 -Mode Install -Executable (Get-Command pythonw.exe).Source
.\scripts\startup.ps1 -Mode Start
```

后台任务名 `NjustWifiLocalMonitor`，端口 `18089`，日志 `%LOCALAPPDATA%\NJUSTWiFi\events.jsonl`。仅停止：

```powershell
.\scripts\stop.ps1
```

移除任务：`.\scripts\startup.ps1 -Mode Remove`。该命令保留配置与账号。也可以通过任务管理器退出手动启动的 `NJUSTWiFi.exe`。界面“暂停”停止自动连接，但保留设置界面服务。

## 无人登录时自动联网（3.9.2 起）

桌面版的“开机启动”现在同时安装 `NjustWifiBootNetwork`：Windows 启动后约 20 秒，由 SYSTEM 运行独立的联网后台，无需用户登录或保存 Windows 密码。首次开启/关闭会出现管理员确认；取消后设置保持原值。原 `NjustWifiLocalMonitor` 仍在登录后启动，负责界面、程序守护、余额和代理客户端。两个后台通过跨会话互斥锁交接；开机后台发现所属用户已经登录（包括锁屏或断开的远程会话）后停止网络操作，用户后台等待正在进行的恢复结束后再接管。

已经开启旧版“开机启动”的用户，升级后在发布包目录执行一次以下命令，即可补装开机任务，不必切换现有开关：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Boot-Network.ps1 -Mode Install
```

同时开启“启动后自动监控”。校园网需勾选“记住账号”，确保凭据已保存；仅保存在内存的账号在重启后不可用。备用网络密码留空时，登录前只能复用 Windows 中对所有用户可用的配置；只有当前用户可用的备用配置，应在软件中填写密码。开机后台确有连接需要时通过 WLAN API 创建所有用户可用的网络配置，不在安装时连接或断开 WiFi。驱动、WLAN 服务或网络尚未就绪会自动退避重试（30 秒起，最长 5 分钟）。正常状态只更新同一条持续时间，状态/最近操作保存在 `%ProgramData%\SchoolWiFiConnect\BootNetwork\status.json`。

开机后台只做 WiFi 开关恢复、按顺序连接、校园认证和网络检测，不运行 HTTP 设置服务、不弹网页、不启动任意守护 EXE，也不操作 Clash Verge / FlClash 的桌面开关。UU 等远程软件需要自身已安装、启用可在登录前运行的系统服务和无人值守访问；普通桌面 EXE 守护在用户登录后恢复。BitLocker 开机 PIN、硬件 WiFi 开关、企业网络限制仍由系统处理。

SYSTEM 运行的程序复制到 `%ProgramFiles%\SchoolWiFiConnect\BootNetwork`，程序和任务清单仅管理员/SYSTEM 可写；所属用户可读状态。开机后台只读取该用户已有的网络设置与已保存校园凭据，不把 HTTP 设置界面提升为 SYSTEM，也不读取程序守护清单。当前个人配置修改在下一轮检测时读取，不需要重新安装；更新便携版后如需同步新版开机组件，重新执行 Install（需管理员确认）。此系统副本不会被普通应用内更新静默替换。

查看/移除（移除保留个人数据、已保护的程序副本和审计状态，不改变登录任务）：

```powershell
.\Boot-Network.ps1 -Mode Status
.\Boot-Network.ps1 -Mode Remove
```

源码运行的旧启动脚本仍只注册登录任务；开机联网使用完整桌面发布版中的 `Boot-Network.ps1`。

## 验证与发布

```powershell
python -B -m unittest discover -s tests -q
python scripts/build-release.py
```

构建 Windows 发布包只在开发环境安装 PyInstaller，然后执行：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install pyinstaller
.venv\Scripts\python.exe scripts/build-release.py --exe
```

采用目录式 EXE，避免每次启动将整个 Python 解压到临时目录。运行时无需安装 Python。构建剔除测试框架、Tk、未使用的 bz2/lzma/zstd 压缩库，并移除 Python 文档字符串；保留 HTTPS 和自定义探测能力。原生托盘不加载 WebView2 程序集，窗口关闭后所有网页进程释放。前端无持续动画，隐藏页面停止轮询，后台按检测间隔休眠。

发布仅分享 `dist/NJUSTWiFi-3.9.5-Windows-x64.zip` 或源码 ZIP，禁止直接压缩整个开发目录。桌面包中的 `NJUSTWiFi.exe` 是入口，`NJUSTWiFiWindow.exe` 和 `NJUSTWiFiBackend.exe` 、`NJUSTWiFiProxyBridge.exe` 以及 DLL、`_internal` 均需保留。WebView2 SDK 固定版本和 SHA256 校验，发布包保留其许可证。

3.9.4 扩大右下角拉伸热区：原生窗口按 DPI 缩放至 28 像素，网页右下角增加 24 CSS 像素透明命中区并调用原生窗口拉伸。最大化时隐藏网页热区且禁用拉伸；不扩大其他边缘、不增加可见边框或常驻任务。

日志按本机时区显示完整日期和时间（`YYYY-MM-DD HH:mm:ss`），支持按显示的日期筛选，内容在日志页内部滚动。

设置自动保存、值守启停、手动检测、余额刷新、更新操作、守护软件管理及代理设置均记录操作结果；异步检测另记完成结果。自动维护记录规则修复、代理故障与切换、软件启动及失败。正常网络、代理出口和守护软件仅更新持续时间；重复的相同维护故障合并记录。日志中的软件名称与守护列表一致（优先读取程序产品名称，缺少时使用 EXE 文件名，不含目录）；诊断导出隐藏软件名称，不包含账号、密码、SSID、控制密钥或个人路径。清空日志后保留一条“清空日志”操作记录。

测试与演示需指定独立数据目录，例如 `python -B app.py --demo --serve --data-dir .tmp/demo --port 18090`。演示模式不连接或切换实际 Wi-Fi，不执行校园认证。

## 迁移说明

旧版的账号与基础设置迁入当前用户数据目录；旧虚拟环境、浏览器缓存、日志和历史副本不会加入发布包。程序守护在界面中支持添加、浏览选择、移除、清空和管理员启动设置，复用已有任务；发布包默认没有个人程序配置。日志支持筛选、清空和打开目录。网络及每个守护程序各保留一条当前正常状态，显示持续天、时、分（不足一分钟显示秒），持续正常只更新同一条时长，不新增例行检测记录。断网、认证、切换网络或程序重新启动时记录实际操作，历史正常时长结束后固定。只在日志页可见时更新时长文字；后台每轮检查将最近 100 条日志写为有界快照，不按秒写盘。暂停监控会结束计时，程序重开后不会把停机时间算为正常时长；旧版连续正常记录会合并，重连操作保留。高级设置保留 HTTP 超时、自定义探测和显示认证页面。

已有 DPAPI 凭据首次运行会自动转为 `credentials.json`；之后不再加密。个人账号文件始终保存在用户数据目录，发布包排除这些文件。

## 代理保护与程序分流

守护页可选择 Clash Verge 或 FlClash，再连接客户端。FlClash 需在其“外部控制”中开启本地接口；程序支持本地 HTTP 接口及命名管道，读取本机控制密钥，不使用系统代理连接控制接口。两个客户端分别保留分流设置、控制接口配置和恢复快照。配置教程分三步：进入客户端设置、开启外部控制器、回到 NJUST WiFi 核对 API 与密钥并连接；教程图片使用示例配置，可离线查看。“外部控制器”明文显示实际 API 与密钥，支持自动读取和手动填写，离开输入框自动保存。API 留空回到自动读取；密钥留空保持原值并回显；“自动读取”按钮撤销地址与密钥的手动覆盖。明文仅通过本地会话保护的 `/api/proxy/controller` 设置接口提供，普通状态、日志与诊断不含密钥。演示模式不读取真实客户端密钥。外部接口用于出口检测和分流；Mihomo API 本身没有 Windows 系统代理开关，开关控制由客户端的 Windows UI Automation 控件执行。

给已添加的 EXE 选择“跟随系统”“直连”或“代理 / TUN”。默认跟随系统，代理方式需先选择守护代理组，客户端需处于规则模式。PROCESS-PATH 规则会优先匹配，原有规则保留；重新加载规则时保留当前端口、TUN 状态和手动选择的节点。分流通过客户端的 Mihomo 外部接口应用，不再改写订阅、Script.js 或运行配置文件；任一客户端重新加载配置后，后台每 15 秒核对并补回所设规则。移除的管理规则也会在客户端重载后清理。联网的辅助 EXE 需要分别添加。直连分流仍依赖代理内核。

“代理出口异常时关闭系统代理和 TUN”默认关闭。检测解析实际路由模式：规则模式使用默认代理规则所指向的组，全局模式使用 GLOBAL，然后沿当前选择链找到实际节点。守护代理组不决定检测出口。程序通过选中节点请求两个 HTTPS 204 地址，不会把 GLOBAL 的 DIRECT 当作代理正常，也不会通过自动选择组改测其他健康节点。直连、拦截、选择链异常或控制接口错误均不判作坏节点；检测过程中换了节点时，旧结果作废。

开启后，“立即检测”、自动网络检测与守护页“检测出口”都在两个出口探测失败、物理 WiFi 直连成功后关闭本客户端的系统代理和 TUN。独立后台保护每 15 秒检查，需连续三轮异常；单次出口测试会在本轮确认后切换。探测耗时会延长实际间隔。“检测出口”在开关关闭时仅检查并显示结果，不切换网络。

切换前在本机保存恢复快照，通过“恢复代理”手动恢复，不自动切回。其他客户端的系统代理不被关闭；恢复时若检测到客户端设置已由用户更改，会保留新值。系统代理和 TUN 的关闭、恢复均调用客户端自身的原生开关处理程序，不再直接写 Windows 注册表或客户端开关配置。操作后同时核对客户端保存状态与系统代理/内核 TUN 状态，连续两次一致才记录成功。未确认的操作保留恢复记录，不盲目重复切换；用户手动改动开关后保留新选择。客户端需正常运行并与本程序处于同一 Windows 桌面会话，权限一致；客户端退出、轻量模式销毁窗口、设置弹窗未关闭或界面版本不匹配时会提示未完成，保留记录供手动恢复。密钥仅在本地外部控制器设置中明文回显，不进入状态、日志、诊断或发布包；个人配置不进入发布包。运行时无新增第三方依赖；保护关闭且未配置分流或待清理规则时，后台线程等待，不轮询。原生开关桥接程序约 12 KiB，仅按需启动，完成后退出，不常驻。

3.9.3 修复 FlClash 仪表盘开关名称附带状态文字时的识别，使用客户端仪表盘原生开关。检测到用户已在客户端完整恢复且实际状态一致时，自动撤销旧恢复记录并继续出口检测；部分恢复或显示与实际不一致时记录具体开关，等待用户点击“恢复代理”。该按钮可通过客户端先关再开来重新应用失效的开启状态；自动检测不会自行执行这种重新应用。其他客户端接管系统代理时仍保留其状态。

设置页显示的备用密码可以来自 Windows 已保存的网络配置。应用密码为空时，仅按已配置的 SSID 临时读取 Windows 密码回显，不把它复制进 settings.json；用户自行填写的新密码才保存在应用设置中。

高级设置的“认证时打开学校登录页”只会在校园认证时额外打开系统浏览器，方便手动查看门户；关闭它仍会在后端完成自动认证。通常保持关闭即可。
